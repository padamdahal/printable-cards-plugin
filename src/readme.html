Patient Card Configuration Guide

This guide explains how to configure patient cards in the datastore without needing to understand the rendering code.

A card is made up of one or more sections. Each section can be either:

  • single
  • repeatable

1. Card Structure

{
  "id": "opdSummary",
  "name": "OPD Summary",
  "accessAt": [
    "everywhere",
    "enrollment-dashboard"
  ],
  "sections": [],
  "optionSets": {}
}

2. Card Fields

FieldRequiredDescription
idYesUnique card identifier
nameYesCard name shown in the application
accessAtYesWhere the card should be available
sectionsYesList of card sections
optionSetsNoMapping between attribute/data element IDs and option set IDs
cssNoCustom CSS for the whole card
printNoPrint settings such as orientation and paper size

3. Section Types

There are only two supported section types:

  1. single
  2. repeatable

4. Single Section

A single section is rendered only once.

  • Tracked entity attributes
  • Enrollment information
  • Event information
  • Data element values
  • Static HTML
{
  "id": "1",
  "type": "single",
  "title": "Patient Details",
  "htmlBody": "<table><tr><td>Name</td><td>{attribute:yBYTz1M15tf.value} {attribute:MqBkcXtzszn.value}</td></tr></table>"
}

5. Repeatable Section

A repeatable section is rendered multiple times, once for each matching event.

{
  "id": "2",
  "type": "repeatable",
  "title": "Clinical Summary",
  "programStage": "bqd9yievDDw",
  "htmlHeader": "<table><tr><th>Date</th><th>Complaint</th></tr>",
  "htmlBody": "<tr><td>{event:eventDate}</td><td>{dataElement:Ywk0nodmiOh.value}</td></tr>",
  "htmlFooter": "</table>"
}

6. Placeholder Format

{type:id.property}

Where:

  • type can be attribute, dataElement, or event
  • id is the attribute ID or data element ID
  • property is the field to display

7. Attribute Placeholders

{attribute:ATTRIBUTE_ID.property}
PropertyDescription
valueAttribute value
displayNameAttribute name
optionLabelLabel of selected option set value
createdAtDate attribute value was created
updatedAtDate attribute value was last updated

8. Data Element Placeholders

{dataElement:DATA_ELEMENT_ID.property}
PropertyDescription
valueData value
optionLabelLabel of selected option set value
storedByUser who entered the value
createdAtDate value was created
updatedAtDate value was updated
providedElsewhereWhether value was provided elsewhere

9. Event Placeholders

{event:property}
PropertyDescription
eventDateEvent date
dueDateDue date
statusEvent status
completedDateCompletion date
createdAtEvent creation date
updatedAtEvent last update date
orgUnitOrganization unit name
storedByUser who created the event
eventIdEvent UID

10. Best Practices

  • Use single for patient information, headers, or summary sections
  • Use repeatable for visit history, lab results, or immunization records
  • Keep HTML simple and readable
  • Use optionLabel instead of raw coded values whenever possible
  • Use sortBy and limit for repeatable sections to avoid very long printouts
  • Use card-level CSS instead of repeating inline styles
  • Test cards with real data before production use
